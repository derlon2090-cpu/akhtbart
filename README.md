# اختبار عباقرة الكيمياء التقنية

اختبار عربي متجاوب من 10 أسئلة في أساسيات الكيمياء، مدته 10 دقائق، مع اختيار الصف والشعبة ولوحة إحصاءات وتقارير PDF وCSV ونسخة JSON احتياطية.

## المسارات

- الطلاب: `/students`
- الإدارة: `/admin`

## التخزين والإعداد

يتطلب التطوير المحلي Node.js 22 كما هو محدد في `package.json`؛ بعض حزم Neon Realtime لا تدعم إصدارات Node 20 القديمة.

تستخدم واجهات `/api/quiz/*` و`/api/admin/*` وظائف Vercel وقاعدة PostgreSQL مشتركة على Neon. تُحفظ المحاولة قبل بدء الاختبار مع قيد فريد على البريد المدرسي؛ يحتفظ الخادم بالإجابات الصحيحة ويحسب الدرجة، وتقرأ لوحة الإدارة سجلًا موحدًا يتحدث كل ١٠ ثوانٍ.

أضف متغيرات Vercel التالية إلى بيئة Production قبل تشغيل النسخة:

- `DATABASE_URL`: عنوان اتصال Neon الخاص بقاعدة البيانات.
- `ADMIN_PASSWORD`: كلمة مرور قوية بطول ١٦ محرفًا أو أكثر.
- `ADMIN_SESSION_SECRET`: سر عشوائي بطول ٣٢ محرفًا أو أكثر لتوقيع جلسات الإدارة والاختبار.

طبّق مخطط قاعدة البيانات وبذرة الأسئلة الأولية قبل النشر. لا تضع قيم هذه المتغيرات في Git أو ملفات الواجهة. البريد المدرسي يتحقق من النطاق فقط، ولا يثبت ملكية البريد؛ يلزم OTP أو مزود هوية مدرسي لذلك.

### Neon

- يستخدم التطبيق `@neondatabase/serverless` للاتصال من وظائف Vercel، ويقرأ `DATABASE_URL` من البيئة.
- إعداد المشروع مرتبط بملف `neon.ts`، وتشغيل `neon deploy` يطبّق سياسة الفرع ويسحب متغيرات Neon إلى `.env.local`، وهو ملف مستثنى من Git.
- لتجهيز المخطط والأسئلة الأولية محليًا: `npm run db:migrate`، ويستخدم `DATABASE_URL_UNPOOLED` للترحيلات المباشرة عند توفره.
- للتحقق من البناء وواجهة جلب الأسئلة المتصلة بقاعدة Neon: `npm run build` ثم `npm run smoke:api`.
- في Vercel، اضبط `DATABASE_URL` على فرع الإنتاج نفسه الذي ربطه ملف `.neon`، إضافة إلى `ADMIN_PASSWORD` و`ADMIN_SESSION_SECRET`، ثم أعد النشر.

### تنظيم الأسئلة محليًا باستخدام Ollama

منظّم الأسئلة الذكي في استوديو الاختبارات يعمل محليًا عبر Ollama، ويستخدم JSON Schema داخل `format` ثم يتحقق من الناتج مرة أخرى قبل إضافته إلى الاختبار. لا تُرسل الأسئلة إلى مزود ذكاء اصطناعي سحابي.

تستخرج طبقة الخدمة علامات الإجابة داخل السؤال ومفاتيح الحلول المنفصلة، وتزيل الخيارات المكررة، وتعيد الوسوم والشرح ودرجة الثقة. إذا لم توجد إجابة صريحة يمكن تفعيل الاستنتاج الذكي، لكن المنصة تمنع حفظ أي إجابة مستنتجة حتى يؤكدها المشرف يدويًا. تحديد مصدر الإجابة يتم أيضًا بقواعد برمجية مستقلة، فلا يُعتمد على ادعاء النموذج وحده.

1. ثبّت Ollama وشغّله على `http://127.0.0.1:11434`.
2. ثبّت نموذجًا مناسبًا، مثل `ollama pull qwen2.5:7b` أو `ollama pull llama3.2:3b`.
3. اضبط المتغيرات الاختيارية في `.env.local`:
   - `OLLAMA_HOST=http://127.0.0.1:11434`
   - `OLLAMA_MODEL=qwen2.5:7b`
   - `OLLAMA_TIMEOUT_MS=180000`
4. شغّل المنصة محليًا، ثم افتح «الاختبارات والروابط» وتأكد من ظهور حالة «Ollama محلي متصل».

لاختبار التطبيع وحماية المراجعة دون تشغيل النموذج: `npm run test:ai`.

### منشئ الاختبارات من PDF والصور

- تقبل لوحة المنشئ ملفات PDF والصور والملفات النصية، وتدعم كامل المستند أو نطاقات متعددة مثل `12-25, 40-48`.
- يستخرج PDF.js النص صفحة بصفحة، وينظف الترويسات والتذييلات المتكررة، ثم يستخدم نموذج الرؤية المحلي المحدد في `OLLAMA_VISION_MODEL` للصفحات المصورة التي لا تحتوي نصًا كافيًا.
- التوليد يدعم اختيارًا من متعدد وصح/خطأ وإجابات قصيرة بنسب دقيقة، مع صفحة المصدر واقتباس قصير ونموذج إجابة وكلمات مفتاحية للتصحيح.
- لا تحفظ الأسئلة المولدة قبل أن يراجع المشرف كل سؤال ويؤكد الإجابة والمرجع. فشل مطابقة الاقتباس مع الصفحة يظهر كتحذير ولا يُخفى.
- الحد المحلي للملف 25MB و1000 صفحة للعملية الواحدة. رفع الكتب الكبيرة في نشر Vercel يحتاج تخزين ملفات ورفعًا مباشرًا لأن حدود طلبات المنصة السحابية قد تكون أقل؛ تشغيل Ollama المحلي يتطلب تشغيل الباك إند محليًا أو داخل شبكة موثوقة.

### النزاهة والتصحيح والتقارير

- يمكن خلط الأسئلة والخيارات لكل محاولة، تعطيل النسخ والقائمة اليمنى، تحديد مهلة لكل سؤال، وتسجيل مغادرة التبويب مع قفل تلقائي بعد حد يحدده المشرف.
- تُصحح الأسئلة الموضوعية برمجيًا، ويمكن لـ Ollama تصحيح الإجابات المقالية مقابل نموذج الإجابة والكلمات المفتاحية مع درجة وتبرير ونقاط قوة وفجوات تعلم.
- لكل نتيجة صادرة رمز تحقق عام وQR لا يعرض البريد أو الإجابات. يمكن طباعة تقرير PDF وتصدير كشف CSV أو Excel.
- نتائج المشرف تستخدم Neon Realtime عند توفره، وتعود تلقائيًا إلى تحديث دوري كل خمس ثوانٍ إذا تعذر WebSocket.

إذا لم يُضبط `OLLAMA_MODEL` تختار المنصة تلقائيًا أفضل نموذج متاح من القائمة المدعومة. لا يستطيع باك إند Vercel الوصول إلى Ollama الموجود على جهازك عبر `localhost`؛ لذلك هذه الميزة مخصصة لتشغيل باك إند المنصة محليًا، أو لخادم Ollama خاص داخل شبكة موثوقة.

تبدأ لوحة الإحصاءات المركزية من لحظة تفعيل الخادم. المحاولات القديمة التي بقيت في تخزين متصفح واحد لا تنتقل تلقائيًا، ولا يمكن استعادة سجلات من أجهزة أخرى لم تكن متزامنة أصلًا.

## التحقق من الهوية

يتحقق النموذج من صيغة الاسم والبريد ونطاق البريد، لكنه لا يثبت ملكية البريد أو أن صاحبه طالب مسجل. الاسم العشوائي الواضح يُرفض بقواعد شكلية، ولا يمكن التأكد من واقعية الاسم دون تحقق مدرسي.

## التقارير

- CSV لسجل المحاولات.
- PDF من نافذة الطباعة في المتصفح.
- تعرض لوحة الإدارة سجلات البدء والتسليم والنتائج من قاعدة البيانات المشتركة، وتُحدّث تلقائيًا كل ١٠ ثوانٍ.

## ضوابط التطبيق

- تحتفظ قاعدة البيانات بقيد فريد على البريد المدرسي لمنع محاولتين متزامنتين من تسجيل الطالب مرتين.
- يصحح الخادم الإجابات ولا يرسل مفتاح الإجابات إلى واجهة الطالب.
- تُحمى لوحة الإدارة بجلسة موقعة ومحدودة المحاولات، ولا تُحفظ كلمة المرور أو أسرار الاتصال في ملفات الواجهة.
- تحقق النطاق المدرسي يثبت شكل البريد ونهايته فقط، ولا يثبت ملكية البريد؛ يتطلب ذلك رمز تحقق أو هوية مدرسية.
- منع النسخ في الواجهة قيد بصري ولا يمنع تصوير الشاشة أو تجاوز المتصفح.
